# Agent brief: shared SEO foundation and information architecture

## Mission

Create the shared technical and editorial foundation required by every focus agent. Do not publish net-new topic pages in this assignment. Your work should prevent duplicated schemas, inconsistent breadcrumbs, sitemap omissions, tracking gaps, and keyword cannibalization.

## Repository surfaces

- `src/layouts/BaseLayout.astro`
- `src/pages/resources/[slug].astro`
- `src/pages/services/[slug].astro`
- `src/pages/sitemap.xml.ts`
- `src/lib/resource-posts.ts`
- `src/lib/services.ts`
- `src/lib/booking-tracking.mjs`
- `scripts/seo-check.mjs`
- `src/components/site/Header.astro`
- `src/components/site/Footer.astro`

Preserve unrelated user changes. Do not rewrite existing layouts unless a focused helper materially reduces repeated SEO defects.

## Deliverables

### 1. Create a page-ownership registry

Add `docs/seo/page-ownership.md` with one row per indexable page and these columns:

- URL
- Page type
- Primary intent
- Primary keyword family
- Owning service
- Status: live, planned, incubator, or excluded
- Notes on competing/related URLs

Populate all current pages plus every approved URL from the focus briefs. The registry is editorial governance, not runtime configuration.

### 2. Strengthen automated SEO validation

Extend `scripts/seo-check.mjs` only where the rule is deterministic and low-noise. Add checks for:

- every indexable HTML page appearing exactly once in the sitemap;
- sitemap URLs resolving to generated pages;
- one canonical, title, description, and H1, preserving current limits;
- indexable resource/service pages containing Article/Service schema and BreadcrumbList schema;
- internal links not pointing to redirect sources;
- consultation CTAs on commercial/service pages carrying `data-track-event` and `data-track-placement`;
- duplicate indexable paths generated by separate content registries.

Do not build a brittle keyword-density or word-count checker.

### 3. Establish reusable page primitives

Inventory repeated breadcrumb schema, page breadcrumbs, CTA blocks, and related-content cards. If at least three planned pages need the same element, extract a typed component/helper. Candidate files:

- `src/components/seo/Breadcrumbs.astro`
- `src/components/seo/ConsultationCta.astro`
- `src/lib/seo-schema.ts`

The helper must preserve the homepage visual language and existing analytics attributes. Do not introduce a generic article theme that visually departs from the homepage.

### 4. Define new page registries before vertical pages

If collision, specialty, or multi-location pages are approved, add one typed data registry such as `src/lib/industry-pages.ts` and one renderer at `src/pages/industries/[slug].astro`. The registry must support:

- slug, title, SEO title/description, dates, image and dimensions;
- hero copy, problem/solution sections, proof, FAQs, owning services, related resources;
- Service or WebPage schema plus breadcrumbs;
- explicit `indexable` state so an unapproved draft cannot enter the sitemap.

Do not create the registry until at least one industry page passes its focus-specific validation gate.

### 5. Measurement contract

Document permitted events in `docs/seo/measurement-events.md`. Reuse:

- `consultation_cta_click`
- `service_cta_click`
- `phone_click`
- `email_click`

Define placement naming as `{page_or_cluster}_{section}`. Add new events only for genuinely distinct interactions such as calculator completion; route them through `window.tkTrack` rather than adding another analytics library.

## Acceptance criteria

- Page ownership covers every live and planned indexable URL.
- No shared helper changes the rendered output of existing pages unexpectedly.
- New validation catches deliberate fixture failures and passes the production build.
- A focus agent can add a resource through `resourcePosts` without manually editing the sitemap.
- A future industry page has one documented, typed implementation path.
- `pnpm build`, `pnpm lint`, `pnpm seo:check`, and `pnpm test:tracking` pass.

## Do not do

- Do not add FAQ schema to pages without visible matching FAQs.
- Do not add organization schema to every page; `BaseLayout` already limits sitewide organization/website schema to the homepage.
- Do not add unapproved URLs to navigation or the sitemap.
- Do not invent ratings, review counts, results, locations, authors, or service capabilities.
